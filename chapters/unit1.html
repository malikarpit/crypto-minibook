1.0 Prerequisite Mathematics

📚 Why This Section?

Cryptography is applied mathematics. Every algorithm in this unit is built on three mathematical ideas: binary operations, modular arithmetic, and number theory. This section gives you exactly what you need — no more, no less.

XOR (Exclusive OR)

XOR is the single most important operation in cryptography. It combines two bits according to one rule: same gives 0, different gives 1.

ABA XOR B

011
101
110

Key property: A XOR K XOR K = A. XOR with the same key twice restores the original. This is why XOR is used for both encryption AND decryption with the same key.

Worked Example: XOR Encryption

Plaintext: P = 1011 0101   Key: K = 0110 1100

P = 1011 0101 K = 0110 1100 C = 1101 1001 (XOR, bit by bit) Decrypt: C XOR K = 1101 1001 XOR 0110 1100 = 1011 0101 = P ✓

Modular Arithmetic

Modular arithmetic is "clock arithmetic." a mod n gives the remainder when a is divided by n. The result is always between 0 and n-1.

Examples
17 mod 5 = 2 (17 = 3×5 + 2) 25 mod 7 = 4 (25 = 3×7 + 4) 7 mod 7 = 0 (7 = 1×7 + 0) -3 mod 5 = 2 (always positive: 5-3=2)

Modular addition: (a + b) mod n — used in Caesar cipher, Vigenère.

Modular exponentiation: ab mod n — the foundation of RSA and Diffie-Hellman. The key insight: it is easy to compute gx mod p, but extremely hard to reverse (find x given the result). This one-way difficulty is the Discrete Logarithm Problem.

Prime Numbers & GCD

A prime number is divisible only by 1 and itself (2, 3, 5, 7, 11, 13...). RSA security depends on the fact that multiplying two huge primes is easy, but factoring the product back into primes is computationally infeasible.

GCD (Greatest Common Divisor): gcd(a, b) is the largest number that divides both a and b. Two numbers are coprime if gcd(a, b) = 1. This is required for RSA key selection.

Euler's Totient Function φ(n)

φ(n) counts how many integers from 1 to n are coprime with n.

φ(7) = 6 (all of 1,2,3,4,5,6 — since 7 is prime) φ(p) = p-1 (for any prime p) φ(pq) = (p-1)(q-1) (for two distinct primes p, q) φ(15) = φ(3×5) = 2×4 = 8

This formula is critical for RSA key generation.

1.1 History & Principles of Cryptography

Cryptography (Greek: kryptos = hidden, graphein = to write) is the science of securing communication so that only intended parties can read it. Its counterpart, Cryptanalysis, is the science of breaking cryptographic systems. Together they form Cryptology.

Core Terminology

Plaintext (P): Original readable message.
Ciphertext (C): Scrambled, unreadable output.
Encryption: C = E(K, P)
Decryption: P = D(K, C)
Key (K): The secret parameter that controls encryption/decryption.

Q1. State Kerckhoffs's Principle and explain why it matters for modern cryptography.
Kerckhoffs's Principle: A cryptosystem must be secure even if everything about the system EXCEPT the key is public knowledge. This matters because: (1) algorithms eventually leak or are reverse-engineered; (2) security through obscurity creates single points of failure; (3) public algorithms undergo global scrutiny (AES was tested by thousands of cryptographers for 5 years before standardization).
Q2. What is Shannon's confusion-diffusion framework?
Confusion: obscure the relationship between key and ciphertext (S-boxes in AES/DES achieve this via non-linear substitution). Diffusion: spread the influence of one plaintext bit across many ciphertext bits (ShiftRows + MixColumns in AES spread each byte across all 16 bytes over 2 rounds). Together they prevent statistical analysis of ciphertext from revealing key or plaintext patterns.
  • Cryptography goals: Confidentiality, Integrity, Authentication, Non-repudiation (CIA + N)
  • Kerckhoffs's Principle: security depends only on key secrecy, NOT algorithm secrecy
  • Shannon's framework: Confusion (S-boxes) + Diffusion (permutations) → secure block ciphers
  • Historical milestone: Enigma broke by Turing/Bletchley because it relied on operational security, not mathematical hardness

1.2 Kerckhoffs's Principle & Shannon's Design Laws

Kerckhoffs's Principle (1883)
"A cryptographic system should be secure even if everything about the system, except the key, is public knowledge."

Auguste Kerckhoffs stated 6 principles for military ciphers. The 2nd — now called Kerckhoffs's Principle — is the foundation of modern crypto design. AES, RSA, and all modern algorithms are completely public. Only the key is secret.

⚠️
Security through Obscurity = FAILURE. Proprietary/secret algorithms cannot be vetted by the public. They will be reverse-engineered. Once the algorithm is exposed, the entire system is broken forever — you cannot change it without replacing every device. Only ephemeral keys should be secret.

Shannon's Two Design Properties

Claude Shannon (1949) defined two properties that every secure cipher must have:

PropertyDefinitionGoalHow it's achieved in AES
Confusion Makes the relationship between key and ciphertext as complex as possible Prevent deducing the key from ciphertext statistics SubBytes (S-box substitution) — non-linear
Diffusion Spreads the influence of each plaintext bit across many ciphertext bits (Avalanche Effect) Destroy statistical patterns from plaintext ShiftRows + MixColumns — linear permutation
💡
Avalanche Effect: In a well-designed cipher, flipping a single bit in the plaintext or key should change approximately 50% of the ciphertext bits. DES and AES both exhibit this. It makes mathematical pattern analysis useless.
⚡ Extra: Perfect Secrecy (Shannon, 1949)

Shannon mathematically defined Perfect Secrecy: a cipher has perfect secrecy if the ciphertext gives zero information about the plaintext. Formally: P(M | C) = P(M) — knowing the ciphertext does not change the probability of any plaintext.

Shannon proved that perfect secrecy requires the key to be at least as long as the message and uniformly random — which is exactly the One-Time Pad. No computationally-bound cipher (like AES) achieves perfect secrecy; they achieve computational security — breaking them takes more resources than any attacker possesses.

1.3 Classical Ciphers

Classical ciphers are historically important and still appear in exams. They establish the two fundamental operations — substitution (replace letters) and transposition (rearrange letters) — that modern block ciphers use in every round.

Caesar Cipher (Shift Cipher)

Each letter is shifted by a fixed number k. With 26 letters, the entire key space is only 25 — trivially brute-forced.

Caesar Cipher Formula
Encryption: C = (P + k) mod 26
Decryption: P = (C - k) mod 26
Example: Encrypt "HELLO" with k=3
H(7) + 3 = K(10) E(4) + 3 = H(7) L(11)+ 3 = O(14) L(11)+ 3 = O(14) O(14)+ 3 = R(17) Result: KHOOR

Vulnerability: Only 25 possible keys. Also broken by frequency analysis — in English, E, T, A, O, I, N are most common. The most frequent letter in ciphertext likely maps to E.

Playfair Cipher (Polygram Substitution)

Encrypts pairs of letters (digraphs) using a 5×5 grid built from a keyword. Combines I/J into one cell. Beats simple frequency analysis since there are 26×26 = 676 possible digraphs vs 26 single letters.

Grid construction: keyword MONARCHY
Fill grid with keyword (no repeats), then remaining alphabet: M O N A R C H Y B D E F G I K L P Q S T U V W X Z

Rules for each digraph (e.g., "HS"):
1. Same row: take letter immediately to the right (wrap).
2. Same column: take letter immediately below (wrap).
3. Rectangle: each letter takes the corner on its own row at the opposite column.

H is at (row2, col2), S is at (row4, col4). They form a rectangle.
H → same row, opposite col = (row2, col4) = B
S → same row, opposite col = (row4, col2) = P
"HS" encrypts to "BP".

⚡ Extra: Index of Coincidence

The Index of Coincidence (IC) measures how non-uniform a text's letter distribution is. English has IC ≈ 0.065. Random text has IC ≈ 0.038. By computing the IC of ciphertext at different offsets (e.g., every 3rd letter, every 4th), the key length is revealed when IC spikes toward 0.065 — because you've aligned letters encrypted with the same shift, restoring English statistics.

🔬 Advanced: ADFGVX Cipher (WW1)

Used by the German Army in WW1. A two-step cipher: first a Polybius square substitution using only the letters A, D, F, G, V, X (chosen because they sound distinct in Morse code), then a columnar transposition. Broken by French cryptanalyst Georges Painvin in 1918. It represents the historical peak of manual cipher design — combining substitution AND transposition in a single system, a concept AES still uses today.

Q1. Why does frequency analysis break Caesar and simple substitution ciphers but NOT Vigenère?
Caesar and substitution maintain letter frequency distribution — 'E' appears ~13% in English, so the most common ciphertext letter is 'E' encrypted. Vigenère uses a repeating keyword, applying different shifts to each position. This flattens frequency distribution across multiple alphabets — unless the key period k is found (Kasiski test), at which point individual Caesar ciphers are analyzed separately.
Q2. The Vigenère cipher with a random, non-repeating key of the same length as the message becomes what?
The One-Time Pad (OTP). When the key is truly random, never reused, and as long as the message, Vigenère provides perfect secrecy — proven by Shannon (1949). No amount of ciphertext analysis can reveal the plaintext without the key, because every possible plaintext of that length is equally likely given the ciphertext.
  • Caesar cipher (shift by k): broken by frequency analysis in seconds — only 25 possible keys
  • Substitution cipher: 26! ≈ 4×10^26 keys but frequency analysis reduces to trivial puzzle
  • Vigenère (polyalphabetic): resists simple frequency analysis; broken by Kasiski test (find key period) + frequency analysis per column
  • OTP (Vigenère with random key = message length): provably unbreakable (Shannon, 1949)

1.4 One-Time Pad & Perfect Secrecy

One-Time Pad (Vernam Cipher, 1917)
The only cipher mathematically proven to be unbreakable. Each bit of plaintext is XOR'd with a corresponding bit of a truly random key. Proved perfectly secret by Shannon in 1949.
OTP Formula
Encryption: Ci = Pi ⊕ Ki
Decryption: Pi = Ci ⊕ Ki

Four Strict Requirements (All must be met)

  1. The key must be truly random (hardware random number generator, not pseudorandom).
  2. The key must be at least as long as the plaintext.
  3. The key must never be reused — not even a single bit overlap.
  4. The key must be kept completely secret.
⚠️
Key reuse destroys OTP security. If C1 = P1⊕K and C2 = P2⊕K, then C1⊕C2 = P1⊕P2. The key disappears, and the attacker has the XOR of two plaintexts — which can be broken using statistical methods (crib-dragging).

Why isn't OTP used everywhere? The key distribution problem. To securely send a 1 GB video, you need a 1 GB key shared beforehand through a separate secure channel — making the original secure channel redundant. It is used in practice for very short, high-security communications (e.g., nuclear command systems historically used OTP-based systems).

1.5 The Feistel Network Architecture

Feistel Network
A symmetric block cipher structure designed by Horst Feistel at IBM in the 1970s. Forms the basis of DES, Blowfish, Twofish, and many others. Its key brilliance: encryption and decryption use the exact same algorithm — only the subkeys are applied in reverse order.

How One Round Works

  1. Split the 64-bit block into two 32-bit halves: Left (L) and Right (R).
  2. Pass Right half through a complex function f(R, Ki) using the round's subkey.
  3. XOR the output of f with the Left half.
  4. Swap: the old Right becomes the new Left; the XOR result becomes the new Right.
Feistel Round i Equations
Li = Ri-1
Ri = Li-1 ⊕ f(Ri-1, Ki)

Decryption: Run the same structure but feed subkeys in reverse order (K16, K15, ..., K1). This symmetry means a single hardware implementation handles both encrypt and decrypt.

💡
Key Insight: The f-function does NOT need to be invertible! Even if f is a one-way function, the Feistel structure guarantees that decryption works perfectly. This is why S-boxes in DES can be highly non-linear (increasing security) without needing to be reversible.

🔬 Advanced: Luby-Rackoff Theorem — Formal Feistel Security

The Luby-Rackoff theorem (1988) is the foundational security proof for Feistel networks. It proves: if f1, f2, f3 are independent pseudorandom functions (PRFs), then a 3-round Feistel is a pseudorandom permutation (PRP) — indistinguishable from a truly random permutation under chosen-plaintext attack. Extending to 4 rounds yields a strong PRP — secure even under adaptive chosen-ciphertext attack (CCA2).

Security Bound (informal)
AdvPRP(F3) ≤ 2 · AdvPRF(f) + q²/2n
q = adversary queries, n = block size. The birthday term q²/2n forces n ≥ 128 bits for modern security — a key reason AES uses 128-bit blocks.

DES uses 16 rounds — far beyond the 4-round theoretical minimum — providing a large security margin. Patarin (2004) later strengthened the bound for 6-round Feistels to beyond-birthday security: O(22n/3) queries instead of O(2n/2), used in wide-block constructions like BEAR/LION for full-disk encryption. The Luby-Rackoff framework also explains why reducing DES to 8 rounds makes it breakable with 237 chosen plaintexts: fewer rounds means the PRF security of each f-function doesn't compound sufficiently.

🔬
Citation: Luby, M. & Rackoff, C. (1988). "How to construct pseudorandom permutations from pseudorandom functions." SIAM Journal on Computing, 17(2), 373–386. One of the most cited papers in provable cryptography.

1.6 Data Encryption Standard (DES) & Triple-DES

DES (Data Encryption Standard)
Adopted by NIST in 1977. IBM's Lucifer cipher, modified by the NSA. A 16-round Feistel network. Block size: 64 bits. Key input: 64 bits, but every 8th bit is a parity bit → effective key strength: 56 bits.

DES Key Schedule: Generating 16 Subkeys

  1. PC-1 (Permuted Choice 1): The 64-bit key is fed through PC-1, which drops all 8 parity bits, producing a 56-bit key. This 56-bit result is split into two 28-bit halves: C and D.
  2. Left Circular Shift: Each round, C and D are shifted left by 1 or 2 positions according to a fixed shift schedule: rounds 1,2,9,16 shift by 1; all others shift by 2.
  3. PC-2 (Permuted Choice 2): The shifted C+D (56 bits) passes through PC-2, which selects 48 bits to form the round subkey Ki.

The DES f-Function (4 Steps)

  1. Expansion (E-box): 32-bit R is expanded to 48 bits by duplicating 16 specific bits. Provides diffusion — each output bit depends on 2 input bits.
  2. Key Mixing: The 48-bit expanded R is XOR'd with the 48-bit round subkey Ki.
  3. Substitution (S-boxes): Split the 48 bits into eight 6-bit chunks. Each chunk passes through one of 8 different S-boxes (lookup tables), compressing 6 bits to 4 bits. This provides non-linear confusion.
  4. Permutation (P-box): The 32 output bits are rearranged by a fixed permutation. Provides diffusion — spreads S-box outputs across all positions for the next round.

How DES S-Boxes Work

An S-box takes a 6-bit input b1b2b3b4b5b6. The outer bits b1b6 select the row; the inner bits b2b3b4b5 select the column.

S-Box 1: Input = 011011
Outer bits: b1=0, b6=1 → Row = 01 binary = Row 1 Inner bits: b2b3b4b5 = 1101 binary = Column 13 Look up S-box 1, Row 1, Col 13 = 5 4-bit output = 0101

The DES designers hardcoded specific S-box values in the 1970s to resist Differential Cryptanalysis — a technique the public did not discover until 1990!

Weaknesses of DES

WeaknessDetails

Triple DES (3DES) & Meet-in-the-Middle Attack

Why not Double DES? Naive double encryption C = E(K2, E(K1, P)) seems to give 112-bit security. But the Meet-in-the-Middle (MitM) Attack reduces this to just 2⁵⁷ operations:

Meet-in-the-Middle Attack on Double DES
  1. With a known (P, C) pair, encrypt P with all 2⁵⁶ possible K1 values. Store all 2⁵⁶ intermediate results in a table.
  2. Decrypt C with all 2⁵⁶ possible K2 values.
  3. Find a match. Complexity = 2⁵⁶ + 2⁵⁶ = 2⁵⁷ — far less than 2¹¹².
3DES Formula (EDE Mode)
C = E(K3, D(K2, E(K1, P)))
If K1=K2=K3, falls back to single DES (backward compatibility). Effective security: 112 bits. Deprecated by NIST in 2017, disallowed after 2023.
⚡ Extra: DES Subkey Generation — Python Code

Your practical (from des.py) implements the full DES key schedule. Here is the annotated flow:

Python — DES Subkey Generation (from your practical)
SHIFT_SCHEDULE = [1,1,2,2,2,2,2,2,1,2,2,2,2,2,2,1]  # shifts per round

def generate_subkeys(key_hex):

    D = key_56[28:56] # Right 28 bits

        key_48 = permute(C + D, PC2)
        subkeys.append(key_48)
        print(f"Round {i+1}: {bin_to_hex(key_48)}")
🔬 Advanced: Differential Cryptanalysis Against DES

Differential Cryptanalysis (DC), discovered publicly by Biham and Shamir (1990) but secretly known to the NSA in the 1970s, is a Chosen-Plaintext Attack. An attacker selects pairs of plaintexts with a specific XOR difference ΔP and encrypts them. By analyzing how ΔP propagates through S-boxes with known probabilities (the differential), the attacker can statistically recover round subkeys. Full DES requires 2⁶⁷ chosen plaintexts for DC — 8-round DES requires only 2³¼ pairs.

🔬 Advanced: 2DES MITM Formal Complexity & Hellman's Time-Memory Tradeoff

The Meet-in-the-Middle (MITM) attack proves that key concatenation does not multiply security. Given a known (P, C) pair, the attacker builds table T = {E(K1, P) → K1} for all 256 values of K1, then for each K2, checks if D(K2, C) ∈ T. Total complexity: O(257) time, O(256) space. A second (P', C') pair eliminates false matches with overwhelming probability.

Complexity Summary
2DES Brute Force: O(2112) time, O(1) space
2DES MITM: O(257) time, O(256) space
Hellman TMTO: T · M² = N² where N = 256. Setting T = M = 237: break DES with 37 GB storage.
3DES EDE resists MITM: its Encrypt-Decrypt-Encrypt structure prevents intermediate values from aligning.

Real-world impact: distributed.net cracked a DES key in 22 hours using distributed MITM in 1999. Hellman's tradeoff is the theoretical foundation for rainbow tables. The result directly justified NIST's requirement for 128-bit minimum key sizes in AES — ensuring MITM still requires O(264) space, making precomputed attacks economically infeasible.

Q1. DES has 56-bit keys yet 64-bit key blocks. Where do the extra 8 bits go?
The extra 8 bits (1 per byte) are parity check bits — used for error detection in key transmission, not encryption. They carry no security. This is why DES has only 2^56 ≈ 72 quadrillion possible keys, not 2^64. In 1998, EFF's "Deep Crack" ASIC exhausted all 2^56 keys in 22 hours and 15 minutes for the DES Cracking Contest.
Q2. 3DES applies DES three times with keys K1, K2, K3 as E(K1, D(K2, E(K3, P))). Why not just use E(K1, E(K2, E(K3, P)))?
The EDE (Encrypt-Decrypt-Encrypt) structure ensures backward compatibility: if K1=K2=K3, 3DES reduces to single DES. This allowed organizations to upgrade hardware incrementally. Additionally, the meet-in-the-middle attack on 2DES (with 2 keys, K1≠K2) reduces security to 2^56 — the same as DES! 3DES with 3 independent keys provides only ~112-bit effective security (still vulnerable to meet-in-the-middle on two of the three keys).
  • DES: 56-bit key (64-bit block, 8 parity bits), 16 Feistel rounds, broken in 22 hours (1998)
  • 3DES-EDE: 112-bit effective security (3 keys), NIST deprecated 2017, prohibited 2024
  • DES broken by: exhaustive key search (brute force) and differential/linear cryptanalysis
  • S-boxes in DES: designed by IBM/NSA to resist differential cryptanalysis (unknown publicly until 1990)

⚡ Extra: Authenticated Encryption (AEAD)

Traditional modes only provide confidentiality. An attacker can still flip bits in the ciphertext and cause the decrypted plaintext to change (bit-flipping attack). Authenticated Encryption with Associated Data (AEAD) provides both confidentiality AND integrity in a single operation. AES-GCM (Galois/Counter Mode) is the most widely used AEAD — it is mandatory in TLS 1.3. It produces both a ciphertext AND an authentication tag. If a single bit of the ciphertext is altered, the tag verification fails and the data is discarded.

🔬 Advanced: AES-GCM Forbidden Attack — Nonce Reuse is Catastrophic

AES-GCM uses GHASH, a polynomial hash over GF(2128), for authentication. The secret GHASH key H = E(K, 0128) is derived from the encryption key. When two messages are encrypted with the same (Key, Nonce) pair, both ciphertexts share identical keystream and the same H. An attacker observing two (C1, T1) and (C2, T2) can form: T1 ⊕ T2 = GHASHH(C1) ⊕ GHASHH(C2). This difference is a polynomial equation in H over GF(2128), solvable in O(1) field operations — directly recovering H.

Forbidden Attack Recovery Chain (Joux, 2006)
Observe: (C₁, T₁) and (C₂, T₂) encrypted with same nonce
Compute: T₁ ⊕ T₂ = GHASHH(L₁, C₁) ⊕ GHASHH(L₂, C₂)
This is a degree-≤t polynomial in H → find roots over GF(2128)
Recovered H allows forging tag T* for any chosen ciphertext C*
If ciphertexts are also known, CTR keystream reuse additionally leaks P₁ ⊕ P₂ → full plaintext recovery.

Real incidents: Amazon Kindle firmware (2013), WPA2 KRACK (2017), and multiple TLS implementations have suffered nonce-reuse vulnerabilities. Fix: Use AES-GCM-SIV (RFC 8452) — a nonce-misuse resistant AEAD that derives H from both the key and nonce, limiting nonce-reuse damage to revealing identical plaintexts only. Or use ChaCha20-Poly1305 which has a larger 96-bit nonce space and less catastrophic nonce-reuse consequences.

The AES State Matrix

AES treats the 128-bit block as a 4×4 matrix of bytes (the "State"). With 16 bytes (128 bits), each cell holds one byte.

State (4x4 bytes): [ a00 a01 a02 a03 ] (Row 0) [ a10 a11 a12 a13 ] (Row 1) [ a20 a21 a22 a23 ] (Row 2) [ a30 a31 a32 a33 ] (Row 3) Loaded column-by-column from input bytes.

The 4 Transformations Per AES Round

Step 1: SubBytes (Confusion)
Every byte in the State is independently replaced using a single 16×16 lookup table — the AES S-box. It is non-linear, providing confusion. The S-box is mathematically constructed from the multiplicative inverse in GF(2⁸) followed by an affine transformation — making it algebraically opaque.
Step 2: ShiftRows (Diffusion)
Each row of the State is cyclically shifted left by its row index:
Row 0: shift 0 (unchanged)
Row 1: shift 1 byte left
Row 2: shift 2 bytes left
Row 3: shift 3 bytes left
This ensures bytes from each column get spread across all 4 columns, achieving diffusion.
Step 3: MixColumns (Maximum Diffusion)
Each column of the State is treated as a 4-element vector and multiplied by a fixed 4×4 matrix over GF(2⁸). Every byte in a column affects every other byte. After MixColumns, each output byte depends on all 4 input bytes of that column. This achieves the avalanche effect. MixColumns is skipped in the final round to make the inverse structure symmetrical.
Step 4: AddRoundKey
A simple bitwise XOR of the State with the 128-bit round subkey. This is the only step that uses the key. Decryption reverses each step: InvSubBytes, InvShiftRows, InvMixColumns, AddRoundKey (same, since XOR is its own inverse).

AES Round Structure

Initial Round: AddRoundKey (with original key) For each of Rounds 1 to N-1: 1. SubBytes 2. ShiftRows 3. MixColumns 4. AddRoundKey Final Round (no MixColumns): 1. SubBytes 2. ShiftRows 3. AddRoundKey
⚡ Extra: Galois Field GF(2⁸) — The Math Behind AES

AES operations work in the Galois Field GF(2⁸) — the finite field of 256 elements (bytes 0x00–0xFF). Two key rules differ from ordinary arithmetic: Addition = XOR (no carries), Multiplication = polynomial multiplication modulo an irreducible polynomial. The AES irreducible polynomial is p(x) = x⁸ + x⁴ + x³ + x + 1 (hex: 0x11B). When a multiplication result overflows 8 bits, XOR with 0x1B (the lower 8 bits of 0x11B) reduces it back to one byte.

GF(2⁸) Multiplication: xtime(b) = 0x02 × b
xtime(b): shift b left by 1 bit; if MSB was 1, XOR with 0x1B Example 1: 0x02 × 0x53 (MSB of 0x53 = 0101 0011 is 0 → no reduction) Shift left: 0101 0011 → 1010 0110 = 0xA6 Result: 0x02 × 0x53 = 0xA6 Example 2: 0x02 × 0x80 (MSB of 0x80 = 1000 0000 is 1 → reduction needed) Shift left: 1000 0000 → 0000 0000 (dropped carry) XOR 0x1B: 0000 0000 XOR 0001 1011 = 0001 1011 = 0x1B Result: 0x02 × 0x80 = 0x1B MixColumns uses these operations: the first row of the MixColumns matrix is [0x02, 0x03, 0x01, 0x01]. Output byte = 0x02×b0 XOR 0x03×b1 XOR b2 XOR b3 (where 0x03×b = xtime(b) XOR b) This ensures every output byte depends on ALL 4 input bytes → avalanche effect.

Why no weak keys in AES? The S-box is built from x−1 in GF(2⁸) followed by an affine map. Since GF(2⁸) is a field, every non-zero element has a multiplicative inverse — the S-box maps each byte to a unique other byte with no fixed points. This algebraic construction is why AES S-boxes have optimal differential and linear cryptanalysis resistance.

🔬 Advanced: AES Key Schedule & Related-Key Attacks

The AES key schedule expands the original key (e.g., 128 bits) into 11 round keys (for AES-128) using a combination of SubWord (S-box on a 4-byte word), RotWord (circular left rotation), and XOR with round constants (Rcon). While AES-128 has no known practical attacks, a related-key attack (Biryukov and Khovratovich, 2009) can break AES-256 in 2111 operations — significantly faster than brute force but still computationally infeasible. This attack exploits weaknesses in the AES-256 key schedule when attackers can query an oracle under related keys. AES-128 and AES-192 remain secure against all known attacks.

🔬 Advanced: XSL Algebraic Attack Controversy & AES S-box Compact Form

The AES S-box has an unusually compact algebraic representation: S(x) = A · x−1 ⊕ c over GF(28), where A is a fixed 8×8 binary matrix and c = 0x63. This algebraic regularity led Courtois and Pieprzyk (2002) to propose the XSL (eXtended Sparse Linearization) attack, claiming AES could be broken by solving a system of ~8,000 multivariate quadratic (MQ) equations in ~1,600 variables per block. The MQ problem is NP-hard in general, but AES produces a highly structured, sparse system that might be exploitable.

AES S-box Algebraic Identity
S(x) = A · xinv ⊕ c    where xinv = x254 in GF(28)
(Fermat: |GF(28)| = 256, so x255 = 1 ⇒ x−1 = x254)
Biclique attack (2011): 2126.1 ops for AES-128 — trivially better than 2128 brute force
Conclusion: AES has no structural algebraic weakness found in practice. XSL complexity claims were later shown to be overoptimistic due to rank deficiencies in the linearization step.

The cryptographic consensus: AES has no known practical algebraic break. The XSL controversy actually strengthened confidence in AES by motivating exhaustive public cryptanalysis. The biclique attack (2011) provides the best known improvement — reducing AES-128 from 2128 to 2126.1 operations — a difference so small it has no practical security implication. AES-128 is expected to remain secure for the foreseeable future against classical adversaries.

Q1. AES has 4 operations per round. State each and its cryptographic purpose (confusion/diffusion).
SubBytes (Confusion): non-linear byte substitution via S-box — breaks algebraic relationships between key and ciphertext. ShiftRows (Diffusion): cyclically shift rows left — ensures bytes from different columns mix. MixColumns (Diffusion): multiply each column by a fixed matrix over GF(2^8) — each byte influences all 4 bytes in the column. AddRoundKey (Key mixing): XOR with round key — only step that uses the key directly. Final round omits MixColumns.
Q2. AES-128 has 10 rounds, AES-192 has 12, AES-256 has 14. Why more rounds for larger keys?
More key material requires more mixing rounds to achieve full diffusion. AES-256's 256-bit key is expanded into 15 round keys (14 rounds + initial key addition). Counterintuitively, AES-256 has a known related-key attack (Biryukov-Khovratovich 2009) reducing security to 2^119 — weaker than AES-128 against related-key attacks. In practice this is not exploitable (related-key attacks require impossible assumptions about key generation).
Q3. Why must AES-CBC have a random (not predictable) IV for each message?
If the IV is predictable (like a counter), an attacker who can submit messages for encryption can test whether their guess matches the plaintext. If IV_n is known in advance, attacker submits P' = P_guess ⊕ IV_n ⊕ IV_old. If E(P' ⊕ IV_n) = E(P_guess ⊕ IV_old) = previously seen ciphertext, the guess is confirmed. This is exactly the BEAST attack on TLS 1.0.
  • AES rounds: SubBytes (confusion/non-linear), ShiftRows (inter-column diffusion), MixColumns (intra-column diffusion), AddRoundKey
  • AES-128=10 rounds, AES-192=12, AES-256=14. State = 4×4 matrix of bytes (128 bits)
  • AES modes: ECB (broken, no IV), CBC (random IV required, padding oracle risk), CTR (stream mode, no padding), GCM (AEAD: encrypt+authenticate, preferred)
  • Best known attack on AES-128: biclique (~2^126.1) — essentially still brute force

1.9 RSA Cryptosystem (Asymmetric Encryption)

📚 Prerequisites for This Section
Modular arithmetic, prime numbers, Euler's Totient φ(n), and the Extended Euclidean Algorithm — all covered in Section 1.0.
RSA (Rivest-Shamir-Adleman, 1977)
The first practical public-key cryptosystem. Security is based on the computational hardness of Integer Factorization: multiplying two 1024-bit primes takes microseconds, but finding those primes given only their product requires billions of years on classical computers.

RSA Key Generation — Step by Step

  1. Select two large primes p and q (in practice, each 1024–2048 bits).
  2. Compute modulus: n = p × q. (n is public; p and q are destroyed after keygen.)
  3. Compute Euler's Totient: φ(n) = (p − 1)(q − 1).
  4. Choose public exponent e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1. Common value: e = 65537 (0x10001 — has only two 1-bits, making modular exponentiation fast).
  5. Compute private exponent d as the modular multiplicative inverse of e: d ≡ e⁻¹ (mod φ(n)), i.e., d×e ≡ 1 (mod φ(n)). Compute using Extended Euclidean Algorithm.
RSA Keys & Operations
Public Key: (e, n)
Private Key: (d, n)

Encryption: C = Me mod n
Decryption: M = Cd mod n

Why Does Decryption Work? (Euler's Theorem Proof)

By key generation: e × d = 1 + kφ(n) for some integer k. Decrypting:

Mathematical Proof of RSA Correctness
Cₐ = (Mᵉ)ₐ = Mᵃᵈ = M¹⁺Kϕ(n) = M¹ × (Mϕ(n))K By Euler's Theorem: Mϕ(n) ≡ 1 (mod n) Therefore: M¹ × 1K = M (mod n) ✓

⚠️
RSA is for key exchange, NOT bulk encryption. RSA 2048-bit is ~100x slower than AES. In practice (e.g., TLS, PGP), RSA encrypts a randomly generated AES session key. The actual data is encrypted with AES. This hybrid approach gets the best of both worlds.
⚡ Extra: RSA Padding — PKCS#1 v1.5 vs OAEP

Textbook RSA (as described above) is deterministic and malleable — encrypting the same message always gives the same ciphertext, and an attacker can multiply ciphertexts to relate plaintexts. Real RSA always uses padding:

  • PKCS#1 v1.5: Pads with random bytes before encryption. Historically used in TLS. Vulnerable to the Bleichenbacher padding oracle attack (1998) — a Chosen-Ciphertext Attack that exploits error messages to decrypt RSA without the private key.
  • OAEP (Optimal Asymmetric Encryption Padding): Uses two hash functions to make padding fully randomized and non-malleable. Provably secure against CCA2 attacks. Required in modern TLS.
🔬 Advanced: RSA & Quantum Threat — Shor's Algorithm

Peter Shor (1994) designed a quantum algorithm that factors integers in polynomial time: O((log n)² (log log n) (log log log n)). On a classical computer, the best known factoring algorithm (General Number Field Sieve) runs in sub-exponential time. A quantum computer with enough qubits running Shor's can break RSA-2048 in hours. Current estimates: a cryptographically relevant quantum computer requires ~4000 logical qubits (millions of physical qubits due to error correction overhead). We are likely 10–15 years away — but the “Harvest Now, Decrypt Later” threat makes post-quantum migration urgent now.

🔬 Advanced: Bellcore Attack — RSA-CRT Fault Injection

RSA decryption is commonly accelerated using the Chinese Remainder Theorem (CRT): compute Mp = Cdp mod p and Mq = Cdq mod q separately (where dp = d mod (p−1), dq = d mod (q−1)), then combine via Garner's formula. This gives a ~4× speedup. However, Boneh, DeMillo, and Lipton (1997) showed that a single fault during CRT computation completely breaks the private key.

Bellcore Attack: Key Recovery from One Faulty Signature
Normal sig: σ = Cd mod n (both Mp and Mq correct)
Faulty sig: σ̃ = CRT(Mp, M̃q) where Mq has a fault

gcd(σ − σ̃, n) = gcd(error · q, p·q) = q ← private prime recovered!
Once q is known: p = n/q, φ(n) = (p−1)(q−1), d = e−1 mod φ(n). Full private key in milliseconds.

Defenses: (1) Verify before returning: recompute σe mod n and check it equals C before returning the signature — a faulty output will fail this check. (2) RSA blinding: multiply the input by a random re, decrypt, then divide by r. Fault injection now produces errors in random-looking data. (3) Avoid RSA-CRT entirely: use EdDSA (Ed25519) which has no CRT-equivalent vulnerability and is deterministic.

Q1. RSA key generation: given primes p=61, q=53, compute n, λ(n), and a valid (e,d) pair.
n = 61×53 = 3233. λ(n) = lcm(60, 52) = lcm(60,52) = 780. Choose e=17 (coprime to 780). d = 17^-1 mod 780 = 413 (verify: 17×413 = 7021 = 9×780 + 1 ✓). Encrypt M=65: C = 65^17 mod 3233 = 2790. Decrypt: 2790^413 mod 3233 = 65 ✓. Real RSA uses 2048-bit primes where n ≈ 2^4096.
Q2. Why is RSA-PKCS#1 v1.5 vulnerable and what replaced it?
PKCS#1 v1.5 padding for RSA encryption has a fixed structure (0x00 0x02 [random] 0x00 [message]). A padding oracle (server returning "valid/invalid" padding) enables Bleichenbacher's million-message attack — recovering plaintext with ~10^6 queries to the server. Replaced by OAEP (Optimal Asymmetric Encryption Padding) using random masks and hash functions — provably secure against CCA2 under the random oracle model.
  • RSA: n=p×q, e coprime to λ(n), d=e^-1 mod λ(n). Encrypt: C=M^e mod n. Decrypt: M=C^d mod n
  • Security: Integer Factorization Problem (IFP). Best algorithm: General Number Field Sieve — sub-exponential
  • RSA-PKCS#1 v1.5 padding: vulnerable to Bleichenbacher CCA2 (~10^6 oracle queries). Use RSA-OAEP
  • RSA-2048 provides ~112-bit classical security. Broken by Shor's algorithm on quantum computers
  • Never encrypt with private key (that's signing). Never decrypt without OAEP padding.

🔬 Advanced: ECC Point Addition Mathematics

Point addition (P + Q = R) on an elliptic curve follows a geometric rule: draw the line through P and Q, find the third intersection with the curve, reflect it across the x-axis to get R. Algebraically, if P=(x₁,y₁) and Q=(x₂,y₂) with P≠Q:

Point Addition on y² = x³ + ax + b
λ = (y₂ - y₁)/(x₂ - x₁) mod p
x₃ = λ² - x₁ - x₂ mod p
y₃ = λ(x₁ - x₃) - y₁ mod p

For point doubling (P + P = 2P): λ = (3x₁² + a)/(2y₁) mod p

Scalar multiplication (k×G) is computed using the double-and-add algorithm (analogous to square-and-multiply for modular exponentiation), taking O(log k) point operations — making it efficient even for k with 256 bits.

🔬 Advanced: Montgomery Ladder & Twist Security

The standard double-and-add algorithm branches on the bits of k: doubling every step, adding only when the current bit is 1. This data-dependent branching leaks k bit-by-bit via timing and power side-channels (Kocher, 1996). The Montgomery Ladder (Peter Montgomery, 1987) eliminates this by always performing both a doubling and an addition each step, selecting the result via a constant-time conditional swap.

Montgomery Ladder Algorithm
R₀ ← ∞, R₁ ← G
For each bit b of k from MSB to LSB:
  (R₀, R₁) ← cswap(b, R₀, R₁)   « constant-time swap »
  R₁ ← R₀ + R₁;  R₀ ← 2R₀
  (R₀, R₁) ← cswap(b, R₀, R₁)
Result: R₀ = k·G   (same operation count regardless of k)

Twist security: An attacker can send a point on the quadratic twist of the curve (a related curve of different group order) instead of a legitimate public key. Scalar multiplication on the twist may leak the private key via small-subgroup attacks if the implementation skips point validation. Curve25519 is specifically designed so its twist has a safe large cofactor, making twist attacks structurally impossible — NIST P-curves require explicit point validation that vulnerable implementations often skip.

1.11 Cryptographic Hash Functions & HMAC

Cryptographic Hash Function
A function H that maps an input of arbitrary length to a fixed-size output (the digest or hash). It is a one-way function — no keys, no decryption. H(M) is easy to compute; finding M from H(M) is computationally infeasible.

Three Security Properties (All Required)

(One-Way)		 Given H(M), it is infeasible to find M. Password hashes: attacker recovers your password from the stored hash.

(Weak Collision Resistance)		 Given M1, infeasible to find M2 ≠ M1 where H(M1) = H(M2). Document signing: attacker replaces a signed document with a malicious one that has the same hash.
Collision Resistance
(Strong Collision Resistance)		 Infeasible to find ANY two distinct inputs M1, M2 where H(M1) = H(M2). Certificate fraud: attacker creates two certificates with same hash but different contents (SHAttered attack on SHA-1, 2017).

Birthday Attack: By the Birthday Paradox, finding a collision for an n-bit hash takes only ~2n/2 operations, not 2n. This is why 128-bit hashes (MD5) offer only ~264 collision resistance — which modern GPUs can exhaust. Always use at least SHA-256 (2128 collision resistance).

SHA-256 Internal Structure (Merkle-Damgård Construction)

SHA-256 uses the Merkle-Damgård construction: the message is padded to a multiple of 512 bits, split into 512-bit blocks, and each block is processed sequentially through a compression function. The output of each compression feeds as input to the next. The final compression output is the hash digest.

Message → Padding → [Block 1] [Block 2] ... [Block N] ↓ ↓ ↓ Initial Hash Value → Compress → Compress → ... → Final Digest (256 bits) Each block: 64 rounds of bit mixing using message schedule words, constants (first 32 bits of cube roots of first 64 primes), and 8 working variables (a,b,c,d,e,f,g,h).

HMAC (Hash-based Message Authentication Code)

A plain hash provides integrity but NOT authentication. An attacker can modify a message AND recompute its hash. HMAC adds a shared secret key — only someone with the key can produce or verify the MAC.

HMAC Construction (RFC 2104)
HMAC(K, M) = H( (K′ ⊕ opad) ‖ H( (K′ ⊕ ipad) ‖ M ) )

ipad = 0x36 repeated to block size  (XOR with K′ → “inner key”)
opad = 0x5C repeated to block size  (XOR with K′ → “outer key”)
K′ = K padded to block size (or hashed if |K| > block size)

Why 0x36 and 0x5C? They differ in every bit position (0x36 XOR 0x5C = 0x6A = 0110 1010) — ensuring the inner and outer keys are maximally different, preventing related-key attacks between the two hash invocations.
HMAC Step-by-Step (why double nesting blocks length extension)
Step 1 (Inner Hash): inner = SHA256( (K ⊕ ipad) ‖ M ) → This produces a 256-bit value that mixes K into M's hash. Step 2 (Outer Hash): HMAC = SHA256( (K ⊕ opad) ‖ inner ) → The outer hash treats the inner result as just 32 bytes of data. Why length extension fails against HMAC: - Attacker knows HMAC(K,M) = SHA256(outer_key ‖ inner) - To extend, attacker needs to continue the SHA256 chain from state = HMAC(K,M) - But that state IS the outer hash's final state, which hashes (outer_key ‖ inner) - Attacker doesn't know outer_key (needs K to compute it) - Even knowing HMAC(K,M), they cannot forge HMAC(K, M‖suffix) without K ✓

The nested two-level hashing specifically prevents length-extension attacks. HMAC's double nesting blocks this because the outer hash key is unknown to the attacker. HMAC-SHA256 is used universally: JWT token signing, TLS 1.2 PRF, API authentication (AWS Signature V4), and cookie integrity.

⚡ Extra: SHA-3 / Keccak — A Different Design

SHA-3 (Keccak) uses a sponge construction instead of Merkle-Damgård. The message is “absorbed” into a large state (1600 bits), then the hash is “squeezed” out. The sponge construction is inherently resistant to length-extension attacks, produces variable-length outputs (SHA3-224 to SHA3-512), and is based on completely different mathematics than SHA-2 — important if SHA-2 is ever broken. This design diversity is why NIST standardized both SHA-2 and SHA-3.

🔬 Advanced: Length Extension Attack, Keccak-f[1600] & BLAKE3

Length Extension Attack (SHA-2 structural flaw): Merkle-Damgård hash functions (SHA-256, SHA-512, MD5) expose their internal chaining state as the final output. Given H(M) for an unknown M, an attacker can compute H(M ‖ pad ‖ M') for any chosen M' — without knowing M — by initializing the SHA-256 state registers (a–h) with the known H(M) value and continuing to compress blocks. This directly breaks the naive MAC construction H(K ‖ M): an attacker knowing H(K ‖ M) can forge H(K ‖ M ‖ suffix). Not vulnerable: HMAC (outer hash prevents extension), SHA-3 (sponge absorbs then squeezes — no resumable chain), BLAKE3 (tree hashing with finalization flags).

Keccak-f[1600] Permutation — 5 Steps Per Round (24 rounds total)
State: 5×5 matrix of 64-bit lanes = 1600 bits
θ (Theta): xi,j ← xi,j ⊕ parity(col i−1) ⊕ rot(parity(col i+1), 1)
ρ (Rho): rotate each lane by a fixed offset (provides bit-level diffusion)
π (Pi): rearrange lanes between positions (inter-lane diffusion)
χ (Chi): xi ← xi ⊕ ((¬xi+1) AND xi+2)  —  only non-linear step
ι (Iota): XOR lane (0,0) with round constant (breaks symmetry)
Full diffusion achieved in 2 rounds; 24 rounds provides 480× the minimum required margin.

BLAKE3 (2020) combines a Feistel-inspired 7-round compression function (inherited from ChaCha20) with a Merkle tree structure, enabling: (1) arbitrary-length output (XOF mode, like SHA-3), (2) full CPU parallelism — each 1 KB chunk processed independently across cores, (3) built-in keyed MAC, PRF, KDF, and XOF modes without overhead. BLAKE3 is typically 10×–20× faster than SHA-256 on CPUs with AVX-512 SIMD, and is used in WireGuard VPN's handshake KDF and the Bao verified streaming content addressing protocol.

Q1. What are the three security properties of a cryptographic hash function and how do their computational costs differ?
Preimage resistance: given H(x), find any x' such that H(x')=H(x). Cost: O(2^n). Second-preimage resistance: given x, find x'≠x such that H(x)=H(x'). Cost: O(2^n). Collision resistance: find any pair (x,y) where x≠y and H(x)=H(y). Cost: O(2^(n/2)) — much cheaper! This birthday bound is why SHA-256 (256-bit) provides only 128-bit collision resistance.
Q2. HMAC provides authentication — explain why H(key || message) alone is insecure (length extension attack).
SHA-256 uses the Merkle-Damgård construction: the final hash state IS the internal state after processing all blocks. An attacker knowing H(key || message) can compute H(key || message || padding || extra_data) without knowing the key — by continuing the hash computation from the known final state. HMAC wraps the hash in two nested calls: H(K_outer || H(K_inner || message)), making the internal state inaccessible to length extension.
  • Hash properties: Preimage resistance (O(2^n)), Second-preimage resistance (O(2^n)), Collision resistance (O(2^(n/2)))
  • MD5 (128-bit): collision-broken in seconds. SHA-1 (160-bit): broken (SHAttered 2017). SHA-256: secure
  • Length extension attack: H(key‖msg) is insecure. Use HMAC: H(K_outer ‖ H(K_inner ‖ msg))
  • Password storage: NEVER use raw SHA-256. Use bcrypt/scrypt/Argon2 (slow, memory-hard) + salt
  • Merkle-Damgård: SHA-256 processes 512-bit blocks iteratively. Final state = hash output

Q1. Kerckhoffs's Principle states that a cipher's security should depend on:
(b) The secrecy of the key only. The algorithm should be public (reviewed by the community). Only the key is kept secret. This is why AES and RSA are completely published standards.
Q2. Which property of a hash function guarantees that it is computationally infeasible to find any two distinct inputs that produce the same output?
(c) Collision resistance. It covers ANY two distinct inputs, not just one specific input. Second pre-image resistance only covers finding a second input that collides with a given specific input.
Q3. DES uses a 64-bit key input but has an effective key strength of only 56 bits. Why?
(b) Every 8th bit (bits 8,16,24,32,40,48,56,64) is a parity check bit used for hardware error detection. PC-1 (Permuted Choice 1) in the key schedule strips these 8 bits, leaving 56 bits for cryptographic use.
Q4. In RSA with p=5, q=11, e=3, what is the private key d?
(b) 27. n=55, φ(n)=(5-1)(11-1)=40. Find d: 3d ≡ 1 (mod 40). 3×27=81=2×40+1. So d=27. Verify: 3×27 mod 40 = 81 mod 40 = 1 ✓
Q5. The Meet-in-the-Middle attack on Double DES reduces the effective security from 112 bits to approximately:
(b) 57 bits. The attacker encrypts from one end (2⁵⁶ operations) and decrypts from the other (2⁵⁶ operations), then matches. Total: 2⁵⁶ + 2⁵⁶ = 2⁵⁷ operations, far less than the 2¹¹² naive expectation.
Q6. Which block cipher mode of operation is vulnerable to the "ECB Penguin" problem?
(c) ECB (Electronic Codebook). Identical plaintext blocks produce identical ciphertext blocks, revealing the structural patterns of the plaintext. When a Linux penguin image was encrypted with ECB, the ciphertext still clearly showed the penguin shape.
Q7. ECC provides the same security level as RSA-3072 with a key size of approximately:
(c) 256 bits. RSA-3072 provides approximately 128-bit security. ECC-256 (P-256 curve) provides the same 128-bit security level. This dramatic difference explains why ECC is preferred for resource-constrained devices.
Q8. The Vigenère cipher is broken by the Kasiski test, which exploits:
(b) Repeated plaintext segments encrypted with the same key segment. When the same plaintext phrase happens to align with the same part of the repeating key, it produces repeated ciphertext. The distance between repetitions is a multiple of the key length, revealing the key length.
Q9. Which step of AES provides the "Confusion" property?
(d) SubBytes. SubBytes applies a non-linear S-box substitution, making the relationship between the key and ciphertext complex and non-predictable — providing Confusion. ShiftRows and MixColumns provide Diffusion by spreading plaintext influence across the ciphertext.
Q10. HMAC provides protection against length-extension attacks that affect H(Key || Message) because:
(b) The outer hash re-hashes the inner hash output. An attacker who knows H(K||M) cannot extend it to H(K||M||extra) without the key, because the final HMAC value is the result of a second hash that the attacker cannot predict without knowing K.
Q11. The One-Time Pad fails in practice primarily because:
(b) The key distribution problem. The key must be truly random, at least as long as the message, and transmitted securely. If you had a secure channel to share the key, you could just use that channel for the message directly. OTP is mathematically perfect but practically unusable for large data.
Q12. Which block cipher mode allows parallel encryption and decryption of independent blocks without an IV chain dependency?
(c) CTR (Counter Mode). Each block is encrypted independently using E(K, Nonce||Counter_i). Different counters mean different keystreams for each block, which can be computed in parallel. This is why CTR is used in AES-GCM for high-speed TLS.
Q13. The DES S-box design provides which cryptographic property?
(b) Confusion. S-boxes are the only non-linear component in DES. They make it mathematically difficult to deduce the round key from the relationship between plaintext and ciphertext. The P-box (permutation) after S-boxes provides diffusion.
Q14. AES-256 requires how many rounds?
(c) 14 rounds. AES-128 uses 10 rounds, AES-192 uses 12 rounds, AES-256 uses 14 rounds. More rounds for larger keys because the key schedule generates more subkeys and the additional rounds increase security margin.
🍡 MediumQ15. When two AES-GCM ciphertexts are encrypted with the same (Key, Nonce) pair, what can an attacker immediately recover?
(b) The GHASH authentication key H. Nonce reuse means both ciphertexts use the same CTR keystream AND the same H. The XOR of the two authentication tags T₁⊕T₂ is a polynomial equation in H over GF(2128), immediately solvable. Once H is recovered, the attacker can forge valid tags for any future message — this is the Forbidden Attack (Joux, 2006).
🔴 HardQ16. According to the Luby-Rackoff theorem, what is the minimum number of Feistel rounds required to construct a strong pseudorandom permutation (secure against adaptive CCA)?
(c) 4 rounds. The Luby-Rackoff theorem proves: 3-round Feistel → PRP (secure under CPA only). 4-round Feistel → strong PRP (secure under adaptive CCA). DES uses 16 rounds — far above the minimum — for a large security margin. This is why the “f-function” (S-boxes + P-box) doesn’t need to be invertible.
🔴 HardQ17. In the Bellcore attack on RSA-CRT, an attacker obtains one faulty signature σ̃ and one correct signature σ. What single operation recovers a private prime?
(b) gcd(σ − σ̃, n). The faulty signature introduces an error only in the mod-q computation. The difference σ − σ̃ is divisible by q (but not p), so gcd(σ − σ̃, p·q) = q. Once q is known, p = n/q and the full private key d is trivially computed. This requires just ONE faulty output and ONE correct output — a devastating real-world threat to smart card RSA.
🍡 MediumQ18. Which of the following hash constructions is NOT vulnerable to a length-extension attack?
(c) HMAC-SHA256(K, M). HMAC’s outer hash H(K′⊕opad ‖ inner_hash) wraps the inner result, so the attacker cannot continue the Merkle-Damgård chain without knowing K. SHA-256(K‖M), MD5(K‖M), and SHA-512(K‖M) all expose their internal state as the hash output, enabling extension without knowing K. SHA-3 is also inherently immune (sponge construction).
🔴 HardQ19. The Montgomery Ladder for ECC scalar multiplication was specifically designed to prevent which class of attack?
(b) Timing and power side-channel attacks. Standard double-and-add processes bits of the scalar k differently (double always, add only when bit=1), leaking k via timing/power traces. The Montgomery Ladder always performs both a doubling and an addition per bit via a constant-time conditional swap (cswap), making the operation count — and thus the power trace — identical regardless of k’s value. This is why Curve25519 mandates Montgomery ladder internally.
💀 ExpertQ20. In the Keccak-f[1600] permutation (SHA-3 core), which is the only non-linear step, and what is its algebraic form?
(c) χ (Chi). All other Keccak steps (θ, ρ, π, ι) are linear over GF(2). Only χ introduces non-linearity via the AND operation: xi ← xi ⊕ ((¬xi+1) AND xi+2). This single non-linear step per round is sufficient when combined with 24 rounds and the other diffusion steps to provide full cryptographic strength. Compare with AES where SubBytes (the S-box) is the sole non-linear step.
