Cryptanalysis and Security

Breaking and defending cryptographic systems. Attack models, side-channel analysis, data protection states, and the legal landscape of cryptography.

3.1 Introduction to Cryptanalysis

Cryptanalysis is the study of analyzing cryptographic systems to find weaknesses. It is the constructive counterpart to cryptography: by understanding how systems can be broken, we build stronger ones. A cryptanalyst attempts to:

  • Recover the plaintext from ciphertext without knowing the key.
  • Recover the key itself (more damaging — all past and future messages exposed).
  • Find a weakness in the algorithm (even if not directly exploitable).
💡
Why study breaking crypto? Every modern algorithm (AES, RSA, SHA-256) was publicly released so the global cryptographic community could try to break it. AES survived a 5-year NIST competition. The attacks that were found against early candidates (CAST, RC6, Serpent) directly strengthened the final Rijndael design. Security through public scrutiny, not obscurity.

3.2 Classical Attack Models

Attack models are classified by what information the attacker has access to. From weakest to strongest:

Attack ModelAttacker HasGoal & MethodReal Example
Ciphertext-Only (COA) Only intercepted ciphertexts Hardest. Uses frequency analysis, statistical patterns, index of coincidence to deduce plaintext/key. Breaking Vigenère cipher using Kasiski test
Known-Plaintext (KPA) Some (plaintext, ciphertext) pairs Map pairs to deduce the key or algorithm. Standard headers (e.g., HTTP, file magic bytes) provide known plaintexts. Allied codebreakers at Bletchley Park exploited Enigma message headers. Orion Technologies case study.
Chosen-Plaintext (CPA) Can choose plaintexts and get ciphertexts from encryption oracle Feed specially crafted inputs to expose algorithm internals. Differential cryptanalysis is a CPA. Breaking DES S-boxes using input pairs with specific XOR differences
Chosen-Ciphertext (CCA) Can choose ciphertexts and get decryptions from decryption oracle Most powerful. Submit modified ciphertexts to extract private key through error messages or timing. Bleichenbacher's PKCS#1 attack against RSA (1998)
Adaptive CPA/CCA Same as above but can adapt queries based on prior responses Interactive attack. Each query refines the next. Much more efficient than non-adaptive. Padding oracle attacks against CBC mode (POODLE, BEAST)
⚡ Extra: Bleichenbacher's Million Message Attack

In 1998, Daniel Bleichenbacher showed that RSA-PKCS#1 v1.5 decryption error messages act as a padding oracle. An attacker intercepts ciphertext C (encrypting message M). They send thousands of modified ciphertexts C' = C × s² mod n to the server. If the server returns "PKCS conformant" (no error), the attacker learns that M×s falls in a certain mathematical range. After ~1 million queries, the attacker reconstructs M entirely without the private key. Fix: OAEP padding. This flaw still existed in many TLS 1.2 implementations in 2017 (ROBOT attack).

3.3 Advanced Attack Techniques

Differential Cryptanalysis

A Chosen-Plaintext Attack technique. The attacker selects plaintext pairs (P, P') with a specific XOR difference ΔP = P ⊕ P', encrypts both, and analyzes how that difference propagates through the cipher's S-boxes. The S-box is not perfectly non-linear — some input differences map to output differences with higher probability than random. By collecting enough (P, P', C, C') pairs and tracing the probable differential paths, the last-round subkeys can be statistically recovered.

Concept: Differential Propagation
Attacker chooses: ΔP = 0x0080_0000 (one bit set) Encrypts 2^47 pairs (P, P⊕ΔP) through DES Observes output differences ΔC Traces most-probable differential characteristic through 15 rounds Recovers Round 16 subkey with high probability Repeat for other subkey bits → full key recovered

Linear Cryptanalysis

A Known-Plaintext Attack. The attacker finds a linear approximation equation relating plaintext bits, ciphertext bits, and key bits with probability p ≠ 0.5. If p > 0.5, the approximation holds more often than chance. With enough (P, C) pairs, statistical analysis reveals key bits. Introduced by Mitsuru Matsui in 1993; he broke full 16-round DES using 2³̓ known plaintexts.

Birthday Attack (against Hash Functions)

By the Birthday Paradox, in a group of 23 people, there's a 50% chance two share a birthday. For an n-bit hash, you need only ~2ⁿ⁄² random inputs to find a collision with 50% probability (not 2ⁿ as naively expected). This is why a 128-bit hash (MD5) is broken: 2⁶⁴ operations to find a collision is feasible on modern hardware.

HashOutput SizeCollisions Require (Birthday)Preimage Requires

SHA-1160 bits~2⁸⁰ (SHAttered 2017)~2¹⁶⁰

Rainbow Table Attack

Precomputed tables mapping hash outputs back to plaintext passwords. Instead of brute-forcing at attack time, the work is done once, stored (terabytes), and lookups are instant. Defeated by salting: a unique random string appended to each password before hashing means the entire table must be recomputed for every individual salt — computationally impossible.

Replay Attack

An attacker captures a valid encrypted transmission (e.g., an authenticated login packet) and retransmits it later to replay the same authenticated action without knowing the content. Defeated by: Nonces (unique random numbers per session), timestamps, and sequence numbers.

Man-in-the-Middle (MitM)

The attacker positions themselves between two communicating parties, intercepting and relaying (possibly modifying) all communications. Both parties believe they are communicating directly. Defeated by: Authentication via digital certificates (PKI) — the server proves its identity, making impersonation cryptographically impossible.

🔬 Advanced: Padding Oracle Attacks (POODLE, BEAST)

Padding oracle attacks exploit CBC mode padding validation. When AES-CBC decryption produces invalid PKCS#7 padding, the server returns a specific error. An attacker can submit modified ciphertext blocks, observe which ones produce "valid padding" errors (vs "invalid padding"), and byte-by-byte deduce the plaintext without the key. BEAST (2011) exploited TLS 1.0 CBC with predictable IVs. POODLE (2014) exploited SSLv3 CBC. Both forced TLS upgrades. Defense: use AEAD ciphers (AES-GCM) that authenticate before decrypting, eliminating the padding oracle entirely.

Q1. Differential cryptanalysis is a CPA. What two things must the attacker choose and observe?
Choose: plaintext pairs (P, P') with a specific XOR difference ΔP = P ⊕ P'. Observe: corresponding ciphertext pairs (C, C') and their difference ΔC = C ⊕ C'. By analyzing which ΔC values occur with higher-than-random probability, the attacker traces differential characteristics backward through S-boxes to deduce round subkeys.
Q2. For a 128-bit hash (MD5), how many operations does a birthday attack require to find a collision?
~2^64 operations (birthday bound = 2^(n/2) where n=128). This is computationally feasible on modern hardware — MD5 collisions have been computed in seconds since 2004. By contrast, SHA-256 has a 2^128 birthday bound, which remains secure.
Q3. Why can't a pre-computed rainbow table crack a properly salted password hash?
A salt is a unique random string added to each password before hashing: H(password || salt). The rainbow table would need to be recomputed separately for every possible salt value — for a 128-bit random salt, that requires 2^128 × table_size storage. The computation is completely infeasible, making salted hashes immune to precomputation attacks.
  • Differential cryptanalysis (CPA): exploits input-difference→output-difference bias in S-boxes; broke DES with 2^47 chosen plaintexts
  • Linear cryptanalysis (KPA): finds linear approximations of cipher with probability ≠ 0.5; broke DES with 2^43 known plaintexts
  • Birthday attack: collision in n-bit hash needs only 2^(n/2) inputs (not 2^n) — MD5 (128-bit) is broken, SHA-256 (256-bit) safe at 2^128
  • Rainbow tables: precomputed hash→plaintext chains; defeated entirely by adding a unique random salt before hashing
  • Padding oracle attacks (BEAST/POODLE): adaptive CCA exploiting CBC error messages; defense = AEAD ciphers (AES-GCM)

3.4 Side-Channel Attacks

Side-Channel Attack
Attacks the physical implementation of a cryptosystem, not the mathematical algorithm. Even if AES is mathematically perfect, the silicon chip running it leaks information through timing, power consumption, electromagnetic radiation, and sound.
TypeWhat is MeasuredHow Keys LeakReal Case
Timing Attack CPU execution time per operation if(key_bit==1){multiply()} takes longer than no-op. Time differences reveal key bits. Kocher (1995) extracted RSA keys via network decryption timing. OpenSSL had timing bug in ECDSA.
Simple Power Analysis (SPA) Single power trace of chip Square-and-multiply: 'multiply' step is visible as a power spike. One trace reveals key bit pattern. Smart card RSA private key extraction via oscilloscope.
Differential Power Analysis (DPA) Statistical correlation across 1000s of traces Attacker guesses key bits, predicts intermediate values, correlates with power traces. Works even through noise. Smart card AES keys extracted in hours by Kocher et al. (1999). Affects most unprotected chips.
Electromagnetic (EM) Radio frequency emissions CPU circuitry emits EM proportional to data-dependent switching activity. AES keys extracted from laptop using $50 SDR antenna from 1 meter away.
Acoustic High-frequency sound (coil whine) Capacitors on CPU/VRM emit ultrasonic frequencies proportional to processing load. RSA key extracted from a laptop using a smartphone microphone (Ben-Gurion University, 2013).
Cache-Timing (Spectre/Meltdown class) CPU cache access times Cache hits take ~4ns; cache misses take ~100ns. Measuring memory access patterns reveals secret data. Spectre (2018): reads kernel memory from user space via speculative execution + cache timing.
⚡ Extra: Fault Injection Attacks

Beyond passively measuring leakage, fault injection actively disrupts chip operation: glitching the power supply causes random bit-flips in the computation. By deliberately causing a faulty AES encryption and comparing it to the correct ciphertext, Differential Fault Analysis (DFA) can recover the key in as few as 2 faulty computations. Bank ATM cards, embedded HSMs, and FPGA-based crypto need physical tamper protection against this.

🔬 Advanced: Microarchitectural Attacks (Spectre, Meltdown)

Spectre and Meltdown (2018) represent a new class of side-channel attacks exploiting speculative execution and branch prediction in modern CPUs. Spectre tricks the CPU's branch predictor into speculatively executing code that accesses privileged memory. Although the speculative result is discarded by the CPU, it leaves a fingerprint in the L1/L2 cache. By precisely measuring cache access times (the Flush+Reload technique), user-space code can read kernel memory addresses. This breaks the OS memory isolation boundary — entirely in software, no physical access needed. Patches required changes to OS kernels, compilers, and microcode, causing 5-30% performance regressions.

Q1. What is the key difference between SPA and DPA in terms of number of traces required?
SPA uses a SINGLE power trace and extracts key bits from visually distinct features (e.g., the square-multiply pattern in RSA). DPA collects THOUSANDS of noisy traces and uses statistical correlation to separate signal from noise — it works even when individual traces are too noisy to interpret directly.
Q2. How did Spectre use cache timing to read kernel memory from user space?
Spectre exploited CPU speculative execution: a user-space program trained the branch predictor to speculatively execute code that accessed privileged kernel memory. The CPU rolled back the speculative result, but left a fingerprint in the L1/L2 cache. By measuring access times (cache hits ≈4ns vs misses ≈100ns), the attacker inferred which cache lines were touched, revealing the kernel memory contents.
Q3. Why is acoustic cryptanalysis possible without touching the target device?
CPU voltage regulators and capacitors emit ultrasonic frequencies (10-150 kHz) proportional to the computational load. Since RSA and AES have data-dependent power consumption patterns, the acoustic emissions carry key-dependent signatures. Ben-Gurion University (2013) extracted RSA keys using a smartphone microphone placed near a laptop running GnuPG decryption.
  • Side-channel attacks exploit physical leakage (timing, power, EM, acoustic, cache) — not algorithm weakness
  • SPA: single trace reveals key from visible patterns (square-multiply in RSA)
  • DPA: statistical correlation across thousands of traces; works through noise; strongest practical attack on smart cards
  • Cache-timing (Spectre/Meltdown): speculative execution + Flush+Reload technique reads privileged memory from user space
  • Acoustic cryptanalysis: CPU coil whine carries key-dependent signatures extractable with a $50 microphone

3.5 Countermeasures Against Side-Channel Attacks

CountermeasureHow it WorksDefends Against
Constant-Time Programming All cryptographic operations execute in exactly the same number of CPU cycles regardless of key bits. No branches based on secret data. Timing attacks
Masking (Secret Sharing) Internal variables split into random shares: x = x1 ⊕ x2 (random mask). Every operation applied to shares. Mask removed at end. Power trace of one share is statistically independent of the secret. DPA, SPA
Blinding (RSA) Before RSA decryption, multiply ciphertext by a random value r: C' = C×rᵉ mod n. Decrypt C', then divide by r. Power trace reveals C', not C. Timing, power analysis against RSA
Faraday Cage / TEMPEST Shielding Metal enclosure blocks EM emissions. Used in classified government systems (TEMPEST-certified hardware). EM attacks
Hardware Security Modules (HSM) Dedicated tamper-resistant chips. Keys never leave the HSM. Physical tamper triggers key destruction. Used by banks, CAs. Physical access, fault injection, all side-channel
Noise Addition (Power) Random dummy operations inserted to add noise to power traces, defeating DPA correlation. SPA, DPA
Q1. What does "constant-time programming" require for a conditional branch based on a secret key bit?
Both branches (true and false) must execute in EXACTLY the same number of CPU cycles. In practice this means: no early returns based on secret data, no table lookups with secret-indexed memory addresses, and replacing if-else with bitwise operations. Example: instead of if(bit) result=A; else result=B; use result = (A & mask) | (B & ~mask) where mask = -bit (all 1s or all 0s).
Q2. Explain RSA blinding and why it defeats timing attacks.
Before decryption, multiply ciphertext by a random value: C' = C × r^e mod n. Decrypt C' to get M' = M × r, then divide by r to recover M. The timing of the decryption now depends on the random C', not the actual ciphertext C. An attacker measuring timing sees random variation — the correlation with the secret key is broken.
Q3. What is the "masking" countermeasure and which attacks does it defeat?
Masking (secret sharing) splits every internal variable into random shares: a secret value x is stored as (x₁, x₂) where x = x₁ ⊕ x₂ and x₁ is uniformly random. All operations are applied to both shares. The power consumption of each share is statistically independent of x, defeating DPA and SPA — an attacker sees only the random mask, not the secret.
  • Constant-time programming: eliminate all secret-data-dependent branches and memory accesses to defeat timing attacks
  • Masking: split secrets into random XOR shares — each share leaks no information about the secret individually
  • RSA blinding: multiply ciphertext by random value before decryption — timing signature randomized, key unrecoverable
  • HSMs: tamper-resistant hardware — keys never leave the device, physical access triggers key destruction
  • TEMPEST/Faraday cage: blocks EM emanations; required for classified government cryptographic systems

3.6 Data at Rest, in Transit, and in Use

The Three States of Data
A holistic security architecture protects data in all three states. Failure in any one state can compromise everything. Your encrypted disk is useless if the data is stolen from RAM while being processed.
StateDefinitionThreatsCryptographic SolutionExamples
Data at Rest Data stored on hard drives, SSDs, databases, cloud storage, USB drives Physical theft of device, compromised backups, insider access to storage Full Disk Encryption (FDE) with AES-256-XTS. Transparent Database Encryption (TDE). Encrypted backups. BitLocker (Windows), FileVault (macOS), LUKS (Linux), AWS S3 SSE
Data in Transit Data moving across networks: internet, LAN, Wi-Fi, cellular Packet sniffing, ARP poisoning, Wi-Fi eavesdropping, MitM attacks TLS 1.3 for web/API traffic. IPsec VPNs for network-level. MACsec for LAN. HTTPS, SSH, WireGuard VPN, Signal, WhatsApp
Data in Use Data currently loaded in CPU registers, L1/L2 cache, or RAM for active processing Memory-scraping malware, cold-boot attacks (freezing RAM), compromised hypervisor, Spectre/Meltdown Trusted Execution Environments (TEE): Intel SGX, ARM TrustZone, AMD SEV. Hardware-encrypted RAM enclaves the OS cannot read. FHE (computationally expensive but eliminates plaintext in RAM). Apple Secure Enclave (Face ID data), Intel SGX (cloud computing), Azure Confidential Computing
💡
Cold Boot Attack: DRAM retains data for seconds to minutes after power loss (especially when cooled with liquid nitrogen). An attacker can shut down a running computer, spray RAM with freezing agent, move the RAM to another machine, and dump memory contents including encryption keys. Defense: key material should never be stored unmasked in RAM; use hardware key derivation.
⚡ Extra: Intel SGX (Software Guard Extensions)

Intel SGX creates hardware-isolated memory regions called enclaves. Code running inside an enclave is encrypted and integrity-protected by the CPU itself. Even the OS, hypervisor, or BIOS cannot read enclave memory. The CPU decrypts enclave pages only inside the processor die, after verifying the enclave measurement (a hash of its code). Remote parties can attest to the enclave's integrity: the CPU produces a signed quote proving which code is running in the enclave. Used by cloud providers for confidential computing: processing sensitive data (medical records, financial data) on untrusted cloud servers without the cloud provider being able to see the data.

Q1. A laptop with BitLocker enabled is stolen. Which of the three data states is protected and which is NOT?
Protected: Data at Rest. BitLocker (AES-XTS) encrypts the disk — a thief cannot read files without the BitLocker key. NOT protected: Data in Use (if the laptop was running and unlocked, RAM contains plaintext), Data in Transit (BitLocker doesn't encrypt network traffic).
Q2. How does Intel SGX protect data in use, and what threat does it protect against?
SGX creates hardware-encrypted memory enclaves. The CPU encrypts/decrypts enclave memory inside the processor die itself — even the OS, hypervisor, or BIOS cannot read enclave contents. This protects against: compromised OS kernel, malicious cloud hypervisors, and physical RAM scraping. Even the cloud provider hosting the VM cannot see data processed in an SGX enclave.
Q3. What is a cold boot attack and which data state does it affect?
A cold boot attack targets Data in Use. DRAM retains contents for seconds to minutes after power loss (especially when cooled with liquid nitrogen). An attacker powers off a running machine, freezes the RAM sticks, transplants them to another system, and dumps the memory — recovering encryption keys, credentials, and plaintext data. Defense: immediate RAM zeroing on power loss (requires hardware support).
  • Data at Rest: on disk/SSD — protected by FDE (BitLocker/AES-XTS). Threat: physical theft of device
  • Data in Transit: moving over networks — protected by TLS 1.3. Threat: packet sniffing, ARP poisoning, MitM
  • Data in Use: in CPU/RAM — protected by TEE (Intel SGX, ARM TrustZone). Threat: cold-boot, Spectre, compromised hypervisor
  • FHE (Fully Homomorphic Encryption) theoretically computes on encrypted data without decryption — currently 1000-10000x slower than plaintext computation
  • Holistic security requires protection in ALL three states — failure in any one can compromise everything

3.7 Legal & Ethical Issues in Cryptography

GDPR and Encryption

The EU General Data Protection Regulation (GDPR, 2018), Article 32, explicitly requires organizations to implement “pseudonymisation and encryption of personal data” as a technical security measure. A critical legal benefit: if encrypted data is breached but the encryption keys remain secure, EU regulators may not consider it a reportable data breach (encrypted data is “unintelligible” to unauthorized parties). This saves companies from the mandatory 72-hour breach notification and potential fines of up to 4% of global annual revenue.

Export Control (Wassenaar Arrangement)

Cryptography is classified as a “dual-use” technology — it has both civilian and military applications. Until 1996, the US classified encryption software above 40-bit keys as munitions, restricting export. Today, under the Wassenaar Arrangement (multi-nation treaty), strong cryptography can be exported to most countries but is still controlled for export to embargoed nations (North Korea, Iran, Cuba, Syria). This is why older browsers showed 40-bit “export-grade” cipher suites (the FREAK and Logjam attacks exploited these in 2015).

The “Crypto Wars” and Backdoor Debate

⚠️
Government Position: Law enforcement needs “exceptional access” or “backdoors” to encrypted communications to investigate terrorists and criminals. Examples: FBI vs Apple (2016 San Bernardino iPhone), EU proposed CSAM scanning in end-to-end encrypted messages.
💡
Cryptographic Community Consensus: Mathematical backdoors cannot distinguish between “good guys” and “bad guys.” Any backdoor will be discovered and exploited by malicious actors. The Clipper Chip (1993 US proposal) was broken within months. Weakening encryption makes everyone less secure — including governments themselves. The only solution is strong encryption with no backdoors.

🔬 Advanced: EARN IT Act & Cryptographic Surveillance

The US EARN IT Act (2020, 2022, 2024 versions) would allow Congress to impose conditions on tech companies' legal immunity for user content — conditions that critics argue could functionally mandate client-side scanning of encrypted messages before encryption occurs. This “client-side scanning” approach was proposed by Apple for CSAM detection in 2021 and then withdrawn after massive backlash. Cryptographers argue client-side scanning is a backdoor by another name: any system that can scan plaintext before encryption and report certain content to authorities can be abused to scan for any content. The cryptographic and human rights communities consistently oppose such systems.

Q1. Under GDPR, if a company's encrypted database is stolen but keys remain secure, do they need to report the breach?
Likely not. GDPR Article 33 requires notification only if the breach "is likely to result in a risk to the rights and freedoms of natural persons." Since encrypted data is unintelligible without the key, regulators (including the CNIL and ICO) have confirmed that properly encrypted data breaches may not require the mandatory 72-hour notification — though this is case-by-case.
Q2. What was wrong with the Clipper Chip proposal (1993)?
The US government proposed the Clipper Chip: hardware encryption using the Skipjack algorithm with a government-held key escrow. Every encrypted communication would have a "law enforcement exceptional access" copy of the session key. Problems: (1) Matt Blaze found a backdoor bypass in the protocol within months. (2) A backdoor accessible to "good guys" is mathematically accessible to everyone — foreign intelligence, hackers, corrupt officials. The proposal died but the debate continues today.
Q3. What is the "dual-use" classification of cryptography and why does it matter?
Cryptography is classified as a dual-use technology — it has civilian applications (HTTPS, banking) and military ones (secure communications, weapons guidance). This is why strong encryption was classified as a munition until 1996 in the US. Today's Wassenaar Arrangement still restricts export of strong crypto to certain countries, though most commercial use is now freely exportable. This history explains "export-grade" cipher suites in SSL that enabled FREAK and Logjam attacks.
  • GDPR Article 32: encryption is an explicit technical requirement; encrypted breaches may avoid mandatory notification
  • Wassenaar Arrangement: crypto is "dual-use" — strong encryption still restricted for export to embargoed nations
  • Crypto Wars (1990s–present): governments want "exceptional access"; cryptographers prove mathematical backdoors cannot be limited to authorized users
  • Clipper Chip (1993): key escrow proposal broken within months — example of why backdoors always fail
  • Client-side scanning (Apple, EU CSAM) = backdoor-by-another-name: scans plaintext before encryption, allowing surveillance scope to be expanded silently

3.8 Practice MCQs — Unit 3 (15 Questions)

Q1. An attacker has only intercepted encrypted messages and no other information. This is classified as:
(c) Ciphertext-Only Attack (COA). The weakest attack model — the attacker only has ciphertexts. They must use statistical analysis (frequency analysis, index of coincidence) to deduce the key or plaintext without any known plaintext pairs.
Q2. The SHAttered attack (2017) demonstrated the first practical collision in which hash function?
(c) SHA-1. Google's Project Zero team produced two different PDF files with the identical SHA-1 hash, proving SHA-1 collision resistance is broken. Cost: approximately $110,000 in cloud GPU compute. SHA-1 was already deprecated before this but the attack proved it practically.
Q3. Differential Power Analysis (DPA) differs from Simple Power Analysis (SPA) in that DPA:
(b) DPA is a statistical attack: the attacker collects thousands of power traces, guesses key bits, predicts intermediate values, and computes correlation with power traces. The correct key guess produces a sharp spike in correlation. Works even when individual traces are extremely noisy.
Q4. Rainbow Table attacks against password hashes are defeated by:
(b) Salting. A unique random salt makes every user's hash unique even if they use the same password. Pre-computed rainbow tables become useless because they'd need to be recomputed for every individual salt — computationally infeasible.
Q5. Which data state is protected by Full Disk Encryption (FDE)?
(c) Data at Rest. FDE encrypts data on the storage medium (hard drive, SSD). It protects against physical theft of the device. Once the OS is running and you're logged in, data is decrypted in RAM (data in use) and communicated unencrypted unless TLS is used (data in transit).
Q6. Under GDPR Article 32, what is a key legal benefit of encrypting personal data?
(b) Under GDPR, a breach of encrypted data where the keys remained secure may not be considered a reportable breach, as the stolen data is “unintelligible” to the attacker. This avoids the 72-hour notification requirement and potential fines up to 4% of global annual revenue.
Q7. What is the primary argument against cryptographic backdoors for law enforcement?
(b) Any cryptographic backdoor is a vulnerability that can be discovered and exploited by criminals, foreign intelligence, and hackers — not just authorized law enforcement. The NSA's EternalBlue exploit was stolen and used to create WannaCry ransomware, damaging hospitals worldwide.
Q8. Constant-time programming is a countermeasure specifically designed to prevent:
(b) Timing attacks. Constant-time code ensures all paths through the cryptographic code execute in exactly the same time regardless of the input or key, eliminating the time-based information leakage that timing attacks exploit.
Q9. Differential cryptanalysis is classified as which type of attack?
(c) Chosen-Plaintext Attack. The attacker selects specific plaintext pairs with chosen XOR differences and submits them to an encryption oracle. The structured input is what makes differential cryptanalysis possible — random inputs would not reveal the differential characteristics.
Q10. Data “in use” in CPU registers can be protected using:
(c) Intel SGX / TEE. SGX creates hardware-encrypted memory enclaves that not even the OS can read. FHE theoretically allows computation on encrypted data without ever decrypting in RAM, but is currently too slow for most applications.
Q11. The Birthday Paradox implies that finding a collision in an n-bit hash function requires approximately:
(c) 2ⁿ⁄² operations. This is why a 128-bit hash (MD5) provides only 2⁶⁴ collision resistance — breaking it is feasible. SHA-256 provides 2¹²⁸ collision resistance, which remains secure. This also explains why quantum computers halve hash security (Grover's algorithm gives 2ⁿ⁄² pre-image resistance).
🍡 MediumQ12. Linear cryptanalysis is which attack model, and what does an attacker need from it?
(b) KPA. Linear cryptanalysis (Matsui, 1993) is a known-plaintext attack. The attacker finds a linear equation: P[bits] ⊕ C[bits] ⊕ K[bits] = 0 holding with probability p > 0.5. With 2^43 known plaintexts, the statistical bias in p reveals key bits. This directly broke 16-round DES — the first practical attack on the full cipher.
🔴 HardQ13. RSA blinding defeats timing attacks by introducing which mathematical transformation before decryption?
(b) RSA blinding: before decryption, compute C' = C × r^e mod n. Decrypt: M' = (C')^d mod n = M × r. Then remove blinding: M = M' × r^(-1) mod n. The timing now correlates with random C', not actual C — the side-channel signal is completely randomized. r is a new random value for each operation.
🍡 MediumQ14. Differential Fault Analysis (DFA) against AES can recover the full key from as few as how many faulty encryptions?
(b) 2 faulty encryptions. DFA against AES (Giraud, 2004): inject a fault at Round 8 to flip one byte in the State. Compare faulty ciphertext to correct ciphertext — the difference pattern in the final round reveals the Round 10 subkey byte. Repeating for all 16 bytes with ~32-50 faults recovers the full 128-bit AES key. This is why HSMs and secure chips need tamper-detection to immediately erase keys upon physical disturbance.
💀 ExpertQ15. The Spectre-v1 attack uses which combination of CPU microarchitectural features?
(b) Speculative execution + Flush+Reload cache timing. Spectre-v1 mistrains the branch predictor to speculatively execute: if(x < array1_size) y = array2[array1[x] * 4096] with out-of-bounds x. The CPU speculatively loads secret data (array1[x]) and uses it to index array2 — bringing one of 256 cache lines into L1. CPU detects the bounds check failure and rolls back, but the cache state persists. Attacker measures all 256 possible array2 accesses — the one that's a cache hit (fast) reveals the secret byte. Patch: LFENCE barrier after bounds check.
